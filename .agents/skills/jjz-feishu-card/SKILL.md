# 进京证办理状态飞书卡片

本项目的办理和检查结果，用飞书机器人私信本人时，一律按本规范生成卡片。命令都在项目根目录运行。

- 一辆车一张卡片；多辆车分别生成、分别发送。
- 卡片只展示结果：不加按钮、表单和回调，不发 post 富文本（`--markdown`）。
- 卡片由 `build_card.py` 生成，不手写 JSON，也不在脚本输出上增删组件。规范要改时，先改脚本，再同步改下面的「卡片规范」，两边保持一致。

## 生成

1. 把每条 jjz 命令的输出存到临时目录（`$TMP` 指你的临时目录）。退出码为 2 时也照常保存输出。
   ```sh
   jjz status > "$TMP/status.json"
   jjz run --scheduled > "$TMP/run.json"
   jjz run --submit --scheduled > "$TMP/submit.json"   # 只在本次确实提交时运行
   ```
   本次提交过的话，提交后再运行一次 `jjz status > "$TMP/status.json"`，让证件列显示提交后的状态。
2. 生成卡片：
   ```sh
   python3 .agents/skills/jjz-feishu-card/build_card.py --mode apply \
     --status "$TMP/status.json" --run "$TMP/run.json" --submit "$TMP/submit.json" > "$TMP/card.json"
   ```
   - `--mode apply`：会提交的办理任务；`--mode check`：只检查、不提交的任务。
   - `--submit`：只有本次提交过才传。
   - `status` 已经失败（凭证失效、网络错误）、没有运行 `run` 时，只传 `--status`。
   - `--permit inside`：本次办理的是六环内证时传；不传时取 `run` 输出里的 `permit`，再没有就按六环外证。
   - `--title`：一次性任务需要别的标题时才传，例如 `--title "进京证状态复查"`。

## 发送

接收人是本人的飞书 open_id，从环境变量 `FEISHU_OWNER_OPEN_ID` 读取。它属于本机私有配置，不写进仓库；从哪里取得由调用方（例如定时任务说明）给出，并在发送的同一条命令里设置。没有取得时不要猜测接收人，停下并在汇报里说明。

```sh
lark-cli im +messages-send --as bot --user-id "$FEISHU_OWNER_OPEN_ID" --msg-type interactive \
  --idempotency-key "$KEY" --content "$(cat "$TMP/card.json")"
```

- `KEY` 用 `<任务名>-<YYYYMMDD-HHMM>`，时间取北京时间。
- 返回 `"ok": true` 才算发送成功。失败时按报错处理后重发一次，`KEY` 末尾加 `-2`。
- 仍然失败时改发纯文本：用同样的参数加 `--format text` 生成文本，再用 `lark-cli im +messages-send --as bot --user-id "$FEISHU_OWNER_OPEN_ID" --text "<文本>" --idempotency-key "$KEY-text"` 发送，并在汇报里说明卡片发送失败。

## 卡片规范

### 结构

从上到下固定为下面 5 块，不增不减：

1. **标题栏**：标题是「进京证办理」（办理任务）或「进京证办理检查」（检查任务）；副标题是「`MM-DD HH:MM` 办理/检查 · 脱敏车牌」，时间取 jjz 输出的 `checked_at`；图标 `approval_colorful`；右侧放一个状态标签。
2. **一句话结论**：一行加粗文字，同时用作消息列表里的摘要。
3. **证件双列**：左列是本次办理的证，底色用「主色-50」，状态用大号字；右列是另一类证，底色 `grey-50`。每列三行：证件名（灰色小字）、状态（加粗）、起止日期（灰色小字）。
4. **四个短字段**：办理结果（检查任务叫「核验结果」）、本次提交、可办状态、六环内剩余，两两一行。
5. **温馨提示**：`grey-50` 色块，标题「温馨提示」，正文一两句。输出带 `relogin` 时，在这一块上方加一行灰色小字：`succeeded` 写「已自动重新登录并保存新凭证」，`shared` 写「已使用同账号其他配置刚取得的新凭证」，`failed` 写「自动重新登录失败」。

### 配色

| 结论 | 什么情况 | 标题栏 | 标签 |
| --- | --- | --- | --- |
| 已通过 | `approved`，或已有「审核通过」的待生效、生效中新证 | green | 「已通过」green |
| 审核中 | `accepted`、`verified`，或已有审核中的申请 | blue | 「审核中」yellow |
| 无需办理 | 其他 `wait`：未到续办日、内证仍有效、未到最早时间等 | grey | 「无需办理」neutral |
| 待提交 | `preview`：已可办理但没有提交 | orange | 「待提交」orange |
| 需核对 | `blocked` | orange | 「需核对」orange |
| 异常 | `uncertain`、`rejected`、`error`、凭证失效 | red | 「异常」red |

只有审核通过才用绿色。已受理、审核中都不能算通过。

### 文案

- **日期**：与当前同一年写 `MM-DD`，跨年写 `YYYY-MM-DD`，起止之间用「至」。没有结束日期写「`MM-DD` 起 · 结束日期待定」。
- **一句话结论**：已通过写「六环外证已审核通过，`MM-DD` 至 `MM-DD`」；审核中写「已提交 `MM-DD` 起的六环外证申请，等待审核」；无需办理写「暂不需要办理六环外证」；需核对写「办理被拦下，本次未提交」；凭证失效写「凭证已失效，本次未办理」（检查任务写「本次未能检查」）。
- **证件状态**：沿用 jjz 输出的状态原文，例如「审核通过(待生效)」。每类证只列开始日期最新的一条；没有记录时写「无记录」，日期写「—」；`status` 查询失败、拿不到记录时写「未查询到」。刚提交、查询里还没有新记录时，左列按提交结果写「已受理」「审核中」或「审核通过」，日期写「`MM-DD` 起」。
- **办理结果**：「中文结果 · jjz 的 `reason`」，去掉末尾的「；本次只预览」和句号。`run` 返回 `wait` 但实际已有新证时，按新证写：审核通过写「已通过 · 新证待生效」或「已通过 · 新证生效中」，审核中写「审核中 · 等待审批结果」。
- **本次提交**：提交过写「已提交 · 结果 · `attempt` 前 12 位」；没提交写「未提交 · 原因」（提交开关未开、无需提交、已有申请、已被拦下）；检查任务固定写「未提交（只检查）」。
- **可办状态**：写「外 可办 · 内 不可办」，不写 `true`/`false`。
- **六环内剩余**：写「`N` 次」，没有数据时写「—」。
- **温馨提示**：
  - 已通过、审核中：「请到北京交警 App 确认办理结果，出行前以 App 显示为准。」
  - 无需办理：直接写原因，例如「六环内证仍有效，暂不切换六环外证。」
  - 待提交（办理任务）：「已可办理，提交开关未开，请本人决定是否办理。」
  - 待提交（检查任务）：「办理任务未提交成功，现在仍可办理，请本人决定是否办理。」
  - 需核对：「已被拦下：`reason`，请到 App 核对。」
  - 结果不明：「提交结果不明，请到 App 核实是否已有申请，切勿重复提交。」
  - 被拒绝：「服务端拒绝了申请，请到 App 查看原因。」
  - 凭证失效：「凭证已失效，请在终端运行 auth-set --login 重新登录。」
  - 其他错误：「程序出错：`reason`，请到 App 核对办理情况。」
- 不写「需要你做的」加一长串操作说明，不加 emoji，不加分割线或额外标题。

### 不能出现在卡片里

车牌只用 jjz 输出的脱敏形式。姓名、证件号、地址、坐标、凭证、open_id 和原始接口响应都不能写进卡片。
