# 手机号登录可行性评估

核验日期：2026-10-25。结论：可以将手机号作为登录入口继续开发，但公开资料不足以证明已能从登录一直自动取得续办凭证。后续已实现统一认证接口适配、证书预检和本地业务凭证导入；正常运行仍须经验证的办理 Authorization，完整手机号登录到业务凭证的转换尚未打通。当前进展及实测限制见 [本机登录说明](login-usage.md)。

## 已确认与未知部分

| 环节 | 已有证据 | 当前判断 |
| --- | --- | --- |
| 手机号作为账号登录 | [2026-08-06 官方网页登录指南](https://banshi.beijing.gov.cn/changpinggonggao/202608/t20260806_428663.html)列出用户名/手机号/身份证号、密码及验证码 | 登录入口有官方支持；不等于授权第三方客户端直连接口 |
| 手机号加短信验证码 | [交管办理说明](https://jtgl.beijing.gov.cn/jgj/lszt/659722/10936724/10936734/10937348/index.html)列出北京交警 App 支持手机号、密码或短信验证码 | App 有文档依据，实际版本、挑战验证和接口需在本人设备验证 |
| 电脑网页短信登录 | [统一认证登录页](https://portal.bjt.beijing.gov.cn/p/login/login.html)仍有 2022-11-05 起停用短信登录的提示；2026 指南列出账号密码和扫码 | 不能假设网页与 App 的短信流程相同，也不能把注册短信当登录短信 |
| 登录后取得办理 AUTH | [原项目 issue #13](https://github.com/bihongfly/jinjingzheng/issues/13#issuecomment-3722585683)作者复现京通登录 token 无法用于续签；改用业务请求头 Authorization 后成功 | 这是当前关键缺口：缺少公开、已验证的登录态交换流程 |
| 用户名密码自动登录实现 | [issue #12 作者留言](https://github.com/bihongfly/jinjingzheng/issues/12#issuecomment-3635168673)称做过该功能但未公开 | 仅是作者陈述，不能据此声称本项目已经可用 |
| 无人值守续期与刷新 | 无可验证的 refresh/logout/expiry 协议 | 未知，不能承诺永久免登录 |

## 推荐实现方向

首先做交互式登录：本机输入手机号、密码或一次性验证码，遇到图形/短信/实名核验时由本人完成；拿到经过业务只读查询验证的会话后，才交给现有续办器使用。登录提供凭证，续办器继续负责目标车辆、类型、日期、提交保护及审批核验。

待验证的链路是：手机号登录 → 统一认证会话 → 北京交警/进京证业务会话交换 → 办理 Authorization → `stateList` 只读查询。中间可能存在跳转票据、设备绑定或 SDK 流程，当前没有证据确定具体机制，不能猜接口或直接将京通 token 填入业务请求。

第二阶段再依据真实响应开发刷新。定时任务正常复用有效会话；无法刷新或要求人工校验时停止提交并提示重新登录。密码可以只在交互式登录时使用，长期存储需求另行确定；短信验证码不应保存。当前日志策略继续不输出密码、验证码、Authorization 和原始业务响应。

## 下一步所需的最少本地验证

在本人正常登录、打开“进京证办理”并查询记录的过程中，核对登录请求、登录后的业务会话交换和第一条 `stateList` 请求。只需获取这三阶段的必要协议结构及本人有效凭证；无需真正提交续办申请来验证登录。

若业务流程仅能在手机 App/小程序完成，可先由本人完成一次登录，程序复用经验证的业务会话。若完整交换可在当前 Mac 上完成，再把手机号登录集成到本机 CLI。两种情况下都须以 `stateList` 能返回本人目标车辆作为成功标准。

本评估未请求短信、未输入账号密码、未登录任何本人账号、未绕过验证码或实名核验。后续只对业务接口做过一次无凭证空查询，返回 401；未查询任何本人资料或提交申请。
